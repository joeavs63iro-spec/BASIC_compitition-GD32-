## 1. 整体架构概览

### 初始化流程 (`car_init()`)

```
SysTick 时钟初始化
  → UART0 串口初始化 (printf 调试输出)
  → ADC0 5 通道初始化 (CH10/11/12/13/15, 灰度传感器)
  → 6 按键初始化 (K1~K6)
  → 干簧管初始化
  → 左右电机 PWM 初始化 (TIMER7)
  → 编码器初始化 (TIMER1 + TIMER2 正交解码)
  → PID 参数初始化 (Kp=0.8, Ki=0.2, Kd=0.1)
  → WS2812B RGB 初始化 + 熄灭
  → HC-SR04 超声波初始化
  → TOF400C 激光测距初始化
  → SSD1306 OLED 初始化 + 显示开启
  → 中断初始化 (当前为空)
  → 板载 LED1/LED2 初始化
```

### main 循环中同时运行的功能

```c
while(1) {
    （一下的串口都是既有无线又有有线）
    key1，按键（同一按键控制）检测 → 控制 RGB 尾灯颜色    // 6 色选择
    key2，OLED 显示 ADC 原始值 + 归一化值 ，干簧管状态（检测到则蜂鸣器和rgb同时响起，持续500ms） // 实时传感器数据
    key3，printf TOF400C 距离// 串口调试输出
    key4，电机运动（流程仿照Car_motion）        // 串口调试输出
    key5, 编码器测试（仿照encoder），并串口输出编码器数值。
    key6，巡线控制（定时器完成） // 5 路灰度 PD 控制
    delay_1ms(1000);                 // 1 秒循环周期
}
```

## 2. 系统时钟 (SysTick)

### 当前使用方式

| 项目 | 说明 |
|------|------|
| 源文件 | `Libraries/hefei_libraries/hf_systick.c` |
| 初始化 | `systick_config()` — 配置 SysTick 1ms 滴答 |
| 延时函数 | `delay_1ms(count)` — 毫秒级阻塞延时 |
| 微秒延时 | `delay_1us(count)` — 微秒级阻塞延时 |
| 时间戳 | `get_current_time_us()` — 获取系统运行微秒数 |

### 使用场景

- **全工程通用**：几乎所有模块的初始化、等待、时序控制都依赖 `delay_1ms()`
- **巡线模块**：每 10ms 进行一次 PID 更新（`delay_1ms(10)`）
- **main 循环**：`delay_1ms(1000)` 控制 1 秒循环周期
- **RGB 灯效**：`delay_1ms(time)` 控制颜色持续时间

### 改进建议

- **⚠️ 可改进**：考虑增加非阻塞延时机制（基于 `get_current_time_us()` 的时间差判断），避免长时间阻塞影响实时响应
- **⚠️ 可改进**：main 循环 1 秒周期过长，建议改为基于时间戳的非固定周期调度

## 3. 串口通信 (UART)

### 当前使用方式

| 项目 | UART0 | UART1 |
|------|-------|-------|
| 引脚 | TX=PA9, RX=PA10 | TX=PA2, RX=PA3 |
| 波特率 | 115200 | 115200 |
| 用途 | printf 调试输出 + 蓝牙通信 | 预留（未使用） |
| 工作模式 | **轮询模式 (Polling)** | 未初始化 |

### 实现分析

```c
// car_init.c — 仅初始化了 UART0
uart0_init(UART0);  // 轮询模式

// hf_uart.c — printf 重定向到 UART0
int fputc(int ch, FILE *f) {
    usart_data_transmit(USART0, (uint8_t)ch);
    while(RESET == usart_flag_get(USART0, USART_FLAG_TBE));  // 阻塞等待
    return ch;
}

// gd32f30x_it.c — USART0 中断函数为空
void USART0_IRQHandler(void) {
    ;  // 什么都没做！
}
```

### 关键问题

1. **printf 是阻塞的**：`fputc()` 内部 `while` 等待发送完成，大量 printf 会严重拖慢主循环
2. **接收完全依赖轮询**：`uart_getchar()` 是 `while` 等待接收，如果蓝牙模块发送数据而 CPU 正在执行 `delay_1ms(1000)`，数据会丢失（UART 只有 1 字节硬件 FIFO）
3. **中断服务函数为空**：`USART0_IRQHandler` 已定义但未实现任何逻辑，浪费了中断资源
4. **蓝牙（CH9143）场景下尤其严重**：蓝牙数据异步到达，轮询方式极易丢包

### 改进建议

**🔴 高优先级 — 建议从轮询改为 DMA + 空闲中断 (IDLE)**

对于蓝牙数据接收场景，最佳方案是 **DMA 循环模式 + UART IDLE 中断**：

```
蓝牙模块 (CH9143) → UART0 RX → DMA 循环缓冲区 → IDLE 中断通知帧结束
```

## 4. 直流电机驱动 (L9110S)

### 当前使用方式

| 项目 | 左电机 | 右电机 |
|------|--------|--------|
| PWM1（正转）| PC9, TIMER7 CH3 | PC7, TIMER7 CH1 |
| PWM2（反转）| PC8, TIMER7 CH2 | PC6, TIMER7 CH0 |
| PWM 分辨率 | 1000 步 | 1000 步 |
| 最大速度 | 7000（`MOTOR_MAX_SPEED`）| 7000 |

### 函数接口

```c
// 底层 BSP (HF_Double_DC_Motor)
motor_init(left/right);                       // 初始化
motor_forward(left/right, speed);             // 正转（0~MOTOR_PWM_RES）
motor_backward(left/right, speed);            // 反转
motor_set(motor_num, MOTOR_CW/MOTOR_CCW/MOTOR_STOP, speed);  // 通用设置

// 应用层 (car_motion) — 使用硬编码速度值
car_forward();    // 速度固定 6000
car_backward();   // 速度固定 10000
car_stop();       // 速度 0
car_turnleft();   // 左轮 5000，右轮 10000
car_turnright();  // 左轮 10000，右轮 5000
```

### 改进建议

- **⚠️ 改进**：`car_motion` 应用层的速度值全部硬编码在函数内部（6000/10000/5000），应改为参数化接口，或至少定义为宏常量便于调节
- **⚠️ 改进**：转弯时差速比（5000 vs 10000）也硬编码，建议增加转弯半径参数
- **⚠️ 注意**：`MOTOR_PWM_RES=1000` 但 `MOTOR_MAX_SPEED=7000`，说明 `motor_set()` 内部有缩放逻辑，这个不一致容易造成混淆，建议统一或加注释说明
- **⚠️ 需要改进**：pwm输出频率有误，导致最大占空比速度仍然很小

## 5. 编码器 + PID 闭环控制

### 当前使用方式

| 项目 | 编码器 1 (电机 1) | 编码器 2 (电机 2) |
|------|-------------------|-------------------|
| 定时器 | TIMER1 正交解码 | TIMER2 正交解码 |
| 编码器 A 相 | PA0 (TIMER1_CH0) | PA6 (TIMER2_CH0) |
| 编码器 B 相 | PA1 (TIMER1_CH1) | PA7 (TIMER2_CH1) |
| 计数范围 | 0~65535 (16-bit) | 0~65535 (16-bit) |
| 计数变量 | `motor1_count` | `motor2_count` |
| 方向变量 | `motor1_dir` | `motor2_dir` |

### 核心运动控制函数

| 函数 | 功能 | 说明 |
|------|------|------|
| `Move_Single_Motor(n, mm)` | 单电机定距运动 | 独立控制一个电机走指定距离 |
| `Move_Distance(mm)` | 双电机同步运动 | 两电机同步前进，带超调抑制和同步补偿 |
| `Move_ASYtance(mm1, mm2)` | 双电机异步运动 | 两电机各自走不同距离，适用于差速转弯 |

### 技术特点分析

1. **位置式 PID**（非增量式），积分项有输出限幅防止积分饱和
2. **`constrain()` 宏**用来限制输出在 `[MOTOR_MIN_SPEED(300), MOTOR_MAX_SPEED(7000)]` 之间，防止低速堵转
3. **超调检测**：`Move_Distance()` 中有 `overflag` 标志，检测到超调时反向制动（1.2 倍力度）
4. **双电机同步补偿**：`Move_Distance()` 通过两轮位置差计算同步误差，分别对左右 PID 输出加减 0.3×偏差 + 0.1×累积偏差
5. **防抖停止**：到达目标后延时 20ms 二次确认，防止惯性导致位置判断漂移

### 改进建议

- **⚠️ PID 参数需标定**：当前 Kp=0.8, Ki=0.2, Kd=0.1 可能是经验值，建议在实际负载下通过阶跃响应测试重新标定（增加蓝牙调参功能）
- **⚠️ `Move_ASYtance` 参数顺序不一致**：函数签名是 `Move_ASYtance(target1_mm, target2_mm)` 但调用时是 `Move_ASYtance(14000, 14000)`，而注释示例又是 `Move_ASYtance(-90, 90)`（一正一反转弯），需要确认参数含义
- **⚠️ 编码器线程安全**：`motor1_count`/`motor2_count` 如果在中断中也会被修改，需要 `volatile` 和临界区保护（当前标记了 volatile 且仅在主循环中调用 `update_encoder_values()`，暂时安全，但如果将来改为定时中断调用需注意）
- **💡 可增加**：增量式 PID 作为一种选项，增量式 PID 天然抗积分饱和，适合速度环；位置式 PID 适合位置环，当前使用场景是正确的
- **💡 可增加**：速度环 PID（当前仅有位置环），对于巡线等持续运动场景，速度环 + 位置环的串级控制效果更好

## 7. 6 按键输入

### 当前使用方式

| 按键 | 引脚 | 模式 |
|------|------|------|
| K1 | PA4 | IN_PULLUP |
| K2 | PA11 | IN_PULLUP |
| K3 | PB0 | IN_PULLUP |
| K4 | PB1 | IN_PULLUP |
| K5 | PC12 | IN_PULLUP |
| K6 | PD2 | IN_PULLUP |

### 工作方式

```c
unsigned char key_check(void) {
    if(KEYDOWN == gpio_get_input(K1_PORT, K1_PIN)) {
        key_value = 0x01;
        while(KEYUP != gpio_get_input(K1_PORT, K1_PIN)); // 死等按键释放！
    }
    // ... 重复 6 次类似代码
    return key_value;  // 0x01~0x06 或 0xFF
}
```

### 改进建议

- **🔴 高优先级 — 阻塞式消抖**：`while(KEYUP != ...)` 在按键按住期间完全卡死 CPU，如果用户长时间按住按键，电机控制、巡线、所有传感器将停止工作
- **🔴 代码冗余**：6 个按键的检测代码几乎相同，建议用结构体数组统一处理
- **🔴 k1和k2的引脚反了：6 个按键的检测代码几乎相同，建议用结构体数组统一处理
- **💡 建议改为状态机消抖**：
- **💡 更优方案**：（最后完成）如果定时器资源充足，可用 1ms 定时中断 + EXTI 外部中断组合实现按键扫描，进一步降低 CPU 占用

## 8. ADC 采样 + 灰度巡线

### 当前使用方式

| 项目 | 说明 |
|------|------|
| ADC 外设 | ADC0 |
| 通道数 | 5 通道 |
| 通道分配 | CH10 (最左), CH11 (左中), CH12 (中间), CH13 (右中), CH15 (最右) |
| 传感器类型 | 灰度传感器（电磁巡线） |
| 采样方式 | 软件触发，单次转换 |

### 数据采集流程

```
all_adc_get()                     // 读 5 路 ADC 原始值
  → gxmax()                       // 更新各通道最大值（用于归一化）
  → five_unification()            // 归一化到 0~100
    → seven_filter(channel)       // 每通道采 7 次，排序后取中间 5 个平均
  → diancixunxian()               // PD 控制巡线
```


### 改进建议

- **⚠️ `seven_filter()` 效率低**：每次调用 `adc_get()` 7 次，5 个通道即 35 次 ADC 转换，加上冒泡排序的开销，在 main 循环中每次都执行开销较大。建议改为滑动窗口滤波或一阶低通滤波
- **⚠️ PD 参数需现场调试**：kp=1.9, kd=2.8 的取值依赖于具体的赛道灰度对比度、车速、传感器间距，建议增加运行时可调参数的接口（如通过蓝牙 UART 命令调参）
- **💡 建议增加积分项 (I)**：纯 PD 控制在持续弯道时可能有稳态误差，增加 I 项可以消除
- **💡 ADC 采样可改为 DMA + 定时器触发**：当前是软件逐个触发采样，5 个通道串行采集。改为 TIMER 触发 + DMA 循环传输后，可在后台自动完成多通道采集，CPU 只需从 DMA 缓冲区读取最新值
- **💡 归一化最大值初始化**：`ll_max` 等初始值 3000 是硬编码的，建议在初始化阶段做一次自动校准（原地旋转采集各通道最大/最小值）

## 9. HC-SR04 超声波测距

### 当前使用方式

| 项目 | 说明 |
|------|------|
| 触发引脚 (TRIG) | PC11, OUT_PP |
| 回波引脚 (ECHO) | PC10, IN_PULLDOWN |
| 中断 | EXTI10（下降沿中断） |
| 测距原理 | TRIG 发送 10μs 脉冲 → ECHO 高电平持续时间 × 声速 |

### 改进建议

- **✅ 基本合理**：使用 EXTI 中断测量高电平脉宽是 HC-SR04 的标准做法
- **⚠️ 可改进**：当前中断服务中如果涉及浮点计算或 printf，会严重影响中断响应。建议中断中只记录时间戳，主循环中计算距离
- **⚠️ 异常值处理**：代码中有 `if(ultra != 44444 && ultra != 0)` 来过滤异常值，但 44444 这个魔数不够直观。建议改成 `#define ULTRA_TIMEOUT 44444` 并增加更完善的滤波（如连续 N 次异常才判定为无效）

## 11. SSD1306 OLED 显示

### 当前使用方式

| 项目 | 说明 |
|------|------|
| 驱动 | `HF_OLED` (硬件 I2C) |
| 分辨率 | 128×64 |
| 缓冲区 | `OLED_GRAM[128][8]`（全屏 1KB 显存） |

### 改进建议

- **⚠️ `oled_refresh_gram()` 全屏刷新开销大**：每次调用都写入 128×8=1024 字节，I2C 在 400kHz 下约需 20ms。如果只修改了部分内容，建议改为局部刷新（只更新变化的页）
- **⚠️ 帧率问题**：main 循环中有 `delay_1ms(1000)`，所以目前 OLED 刷新率约 1Hz，暂时不算问题。但未来如果提高循环速率，需注意避免过度刷新
- **💡 可考虑 DMA + I2C**：用 DMA 传输 I2C 数据，释放 CPU
- **⚠️ 显示问题**：在car_adc_sampling的demo中我发现它并不能显示四位数的电感，最大只有三位数，找出问题并改正

### 🔴 关键冲突说明

#### 冲突 1：PA5 — 干簧管 vs TCS34725_2 SCL

干簧管配置为 `IN_PULLUP`（输入上拉），TCS34725_2 SCL 需要输出高低电平。当颜色传感器工作时，SCL 的输出会直接驱动 PA5，如果此时干簧管处于吸合状态（磁铁靠近），可能导致短路风险或读数错误。

**解决方案**：
- 将干簧管转移到空闲引脚（如 PB2 或 PB5）
- 或将 TCS34725_2 的 I2C 改用硬件 I2C1（PB10/PB11）

#### 冲突 2：PA6 — 蜂鸣器 vs 编码器 2A vs TCS34725_2 SDA

这是一个**三重冲突**：
- 蜂鸣器使用 TIMER0_CH0 的 AF 复用功能
- 编码器 2 A 相使用 TIMER2_CH0
- TCS34725_2 SDA 使用软件 I2C

在 `14-testcode` 的 `car_init()` 中，编码器和蜂鸣器都初始化了，颜色传感器也可能工作。**同一引脚不能同时配置为两种不同的复用功能**。

**解决方案**：
- 编码器 2 A 相保持 PA6（优先保证编码器功能）
- 蜂鸣器迁移到空闲引脚如 PA8（使用其他定时器通道）
- TCS34725_2 迁移到硬件 I2C1

## 18. 改进建议汇总

### 🔴 高优先级（影响稳定性/正确性）

| 编号 | 模块 | 问题 | 建议 |
|------|------|------|------|
| 1 | **引脚冲突** | PA5/PA6 被多个外设共用 | 重新分配引脚，消除冲突 |
| 2 | **UART 接收** | 轮询模式接收蓝牙数据，极易丢包 | 改为 **DMA + IDLE 中断** 方案 |
